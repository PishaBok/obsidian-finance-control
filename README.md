# 💸 Бюджет для Obsidian

Шаблон ежемесячного бюджета для [Obsidian](https://obsidian.md/) с интерактивной панелью на **DataviewJS**. Помогает распределять доход, контролировать категории расходов, планировать накопления и учитывать остатки без отдельной таблицы или финансового приложения.

Всё хранится в обычных Markdown-заметках: план — в **Properties**, фактические расходы — в двух редактируемых таблицах, статистика — на автоматически построенной панели.

## Возможности

- **План на месяц:** доход, лимиты категорий, отчисления в финансовую подушку и на путешествия.
- **Три типа категорий:** обязательные, гибкие и накопительные. Накопительные отображаются в сворачиваемом разделе.
- **Автоматический перенос остатков:** неиспользованные средства накопительных категорий учитываются в следующем месяце; перерасход тоже переносится.
- **Учёт продуктов по календарным неделям:** недели с понедельника по воскресенье, даты, прогресс-бары и выделение текущей недели.
- **Перенос недельного остатка продуктов:** экономия увеличивает доступную сумму следующей недели, перерасход уменьшает её. Перенос действует **только внутри одного месяца**.
- **Месячный лимит продуктов:** начинается заново каждый месяц; остаток продуктов из прошлого месяца не добавляется.
- **Показатели бюджета:** фактические траты, остатки, распределённые суммы и отклонения от лимитов.
- **Удобное редактирование:** скрипт добавляет недостающие строки в таблицы точечными изменениями, стараясь не сбрасывать положение курсора.
- **Настройки прямо в Properties:** основные суммы можно менять без правки JavaScript.

## Требования

1. Установленный **Obsidian** (настольная версия).
2. Community plugin [Dataview](https://github.com/blacksmithgu/obsidian-dataview).
3. В настройках Dataview включена опция **Enable JavaScript Queries** (выполнение `dataviewjs`).

Шаблон использует API Obsidian и Dataview, поэтому обычный Markdown-просмотрщик GitHub не отобразит интерактивную панель. Для работы со скриптом используйте Obsidian и режим чтения или Live Preview.

## Установка

1. Скачайте файл шаблона из репозитория и поместите его в папку шаблонов вашего хранилища Obsidian, например `Templates/`.
2. В Obsidian включите встроенный плагин **Templates** и укажите папку с шаблонами в его настройках.
3. Создайте папку для месячных заметок, например `Финансы/`.
4. Создайте в ней заметку с именем **`2026-11`** (формат строго `YYYY-MM`) и вставьте в неё содержимое шаблона через команду *Templates: Insert template*.
5. Для следующего месяца создайте **`2026-12`** в **той же папке** и примените тот же шаблон.
6. Измените суммы в Properties под свой доход и цели, затем заполните фактические расходы в таблицах.

> Важно: для автоматического переноса накопительных остатков месячные заметки должны называться `YYYY-MM.md` и находиться непосредственно в одной папке. Если назвать заметку иначе, панель сообщит о неверном формате имени.

## Настройка бюджета

В шаблоне есть пример распределения **90 000 ₽ в месяц**. Это демонстрационные значения — замените их своими.

```yaml
budget: 90000
currency: ₽
reserve: 17000
reserve_transferred: false
travel: 15000
travel_transferred: false
categories:
  Жилье: 6000
  Продукты: 20000
  Кафе: 7000
  Подписки и связь: 3000
  Спортзал: 3000
  Транспорт / бензин: 3000
  Вещи для дома: 2000
  Развлечения: 3000
  Подарки: 3000
  Здоровье: 1500
  Одежда: 2000
  Техника / личные покупки: 2000
  Прочее: 2500
```

| Поле | Назначение |
| --- | --- |
| `budget` | Доход, который планируется распределить за месяц |
| `currency` | Символ валюты для отображения |
| `reserve` | Сумма на финансовую подушку |
| `reserve_transferred` | Отметка, переведены ли деньги в подушку (`true` / `false`) |
| `travel` | Сумма на путешествия |
| `travel_transferred` | Отметка, переведены ли деньги в фонд путешествий (`true` / `false`) |
| `categories` | Месячные лимиты категорий |

**Примечание:** флаги `*_transferred` изменяют отметку на панели, но **не выполняют перевод денег**. Отчисления в подушку и на путешествия планируются отдельно от расходных категорий.

### Типы категорий

| Тип | Примеры | Что происходит с остатком |
| --- | --- | --- |
| **Обязательные** | Жильё, продукты, подписки и связь, спортзал | Месячный лимит начинается заново; продукты имеют отдельную недельную детализацию |
| **Гибкие** | Кафе, транспорт, развлечения, прочее | Неизрасходованный лимит автоматически не переносится |
| **Накопительные** | Подарки, одежда, техника, здоровье, вещи для дома | Остаток или перерасход учитываются в следующих месяцах |

Типы категорий заданы в объекте `TYPES` внутри блока `dataviewjs`. Для новой категории добавьте её в `categories` и, при необходимости, в `TYPES` и `ICONS`. Новые названия должны совпадать точно. Неизвестные типы стоит явно настроить в коде.

## Как вносить расходы

В нижней части заметки находятся две таблицы:

### 📥 Расходы месяца

Укажите **сумму, потраченную за весь месяц** по каждой категории, кроме продуктов. Это не список отдельных транзакций — при новых тратах обновляйте итог.

| Категория | Потрачено, ₽ |
| --- | ---: |
| Жилье | 5500 |
| Кафе | 3800 |
| Подарки | 1200 |

Недостающие строки по категориям из Properties шаблон добавляет автоматически.

### 🛒 Продукты по неделям

Вносите **общую сумму покупок продуктов за каждую неделю**. Даты недель и строку текущей недели панель формирует автоматически.

| Неделя (Пн–Вс) | Потрачено, ₽ |
| --- | ---: |
| 1 · 26 окт. – 1 нояб. | 0 |
| 2 · 2 нояб. – 8 нояб. | 4140 |

Названия недель в примере иллюстративные: при работе используйте автоматически созданные строки и не изменяйте их номера.

**Как считается перенос:** если недельный ориентир составляет 4 667 ₽, а потрачено 4 140 ₽, следующие 527 ₽ увеличат доступный бюджет следующей недели. Если расходы превысили ориентир, доступная сумма следующей недели уменьшится. На границе месяца перенос обнуляется. Для неполных недель лимит рассчитывается пропорционально числу дней соответствующего месяца.

> Значения в обеих таблицах — накопленные итоги за соответствующий период. Не добавляйте новую строку на каждую покупку: шаблон не является журналом транзакций.

## Как работают накопительные категории

Например, для категории «Подарки» установлен месячный лимит 3 000 ₽:

| Месяц | Добавлено | Потрачено | Остаток категории |
| --- | ---: | ---: | ---: |
| Ноябрь | 3 000 ₽ | 500 ₽ | 2 500 ₽ |
| Декабрь | 3 000 ₽ | 0 ₽ | 5 500 ₽ |
| Январь | 3 000 ₽ | 4 000 ₽ | 4 500 ₽ |

Никакие `carryover_categories` и `carryover_start` в Properties заполнять не нужно. Список переносимых категорий определяется типом `fund` в коде, а **начало истории переносов в текущей версии зафиксировано на `2026-11`** (`carryStart`). Если вы начинаете пользоваться шаблоном позже или хотите учитывать более ранние месяцы, измените эту константу непосредственно в блоке `dataviewjs`.

Расчёт строится на содержимом доступных месячных файлов; остатки не записываются в отдельные поля YAML.

## Полезные замечания

- **Резерв и путешествия — отдельные цели**, а не расходы по категориям. Их фактическое пополнение нужно выполнить самостоятельно.
- **Переносимые остатки — виртуальные конверты.** Они не подтверждают наличие денег на счёте и не синхронизируются с банком.
- **Расходы не подтягиваются автоматически** из банков или сторонних приложений — суммы в таблицах вводятся вручную.
- **Если месяц пропущен**, убедитесь, что история месячных заметок отражает ваши реальные пополнения и траты: расчёт опирается на существующие файлы.
- **Код и интерфейс тесно связаны с названиями разделов.** Не переименовывайте заголовки `📥 Расходы месяца` и `🛒 Продукты по неделям`, не изменив соответствующие константы в скрипте.
- **При копировании шаблона** меняйте только Properties и значения в таблицах, если не планируете изменять саму логику.
